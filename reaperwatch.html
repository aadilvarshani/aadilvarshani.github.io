ReaperWatch.

A Windows EDR, built from scratch, one real mechanism at a time: a C++ agent that watches process creation at the kernel's own speed, and a console that turns that telemetry into alerts.

EDR

Why build one when EDRs already exist

I wanted the mechanical answer to a question detection engineering usually leaves as a black box: how does an EDR find out a process exists, with enough detail to judge it, the instant it happens? Not the detection logic, the layer underneath it. ReaperWatch is me building that layer myself, in the open, including the parts that didn't work the first time.

  1. ETWkernel logger, real time
  2. Enrichlineage, hashes, signer
  3. JSONLdurable, on disk
  4. Ingesttail into SQLite
  5. EQLevery event, every rule
  6. Alertseverity, ATT&CK

The agent starts the NT Kernel Logger in real-time mode with the process flag set, so every process creation on the machine arrives as an event while it happens, not from a poll.

std::vector<BYTE> buffer(size, 0);
auto* p = reinterpret_cast<EVENT_TRACE_PROPERTIES*>(buffer.data());
p->Wnode.BufferSize = static_cast<ULONG>(size);
p->Wnode.Flags = WNODE_FLAG_TRACED_GUID;
p->Wnode.ClientContext = 1;                 // QPC (high-resolution) timestamps
p->Wnode.Guid = kSystemTraceControlGuid;    // marks this as the kernel logger
p->EnableFlags = EVENT_TRACE_FLAG_PROCESS;  // capture process create/exit
p->LogFileMode = EVENT_TRACE_REAL_TIME_MODE;

agent/collectors/etw_consumer.cpp

Each event gets its command line from the PEB, SHA256 and MD5, the Authenticode signer, user context and two levels of lineage. A parent is only recorded if it provably started before the child, so a recycled PID never gets blamed for something it didn't launch.

// PID-reuse guard: a real parent must be no younger than its child. If the
// PID was recycled, the process now holding it started later -> reject it.
const auto child_time = get_process_creation_time(pid);
const auto parent_time = get_process_creation_time(parent_pid);
if (!child_time.has_value() || !parent_time.has_value()) {
    return;  // can't verify -> don't record an unverified parent
}
if (*parent_time > *child_time) {
    return;  // parent started after the child: PID reused, impostor
}

agent/collectors/process_monitor.cpp

Events are appended to a local JSON Lines file, independent of whether anything is reading it. Writes are serialised in case ETW calls back from more than one thread, and a failed write never takes the sensor down.

void append_event_line(const std::string& json_line) {
    std::lock_guard<std::mutex> lock(g_mutex);
    std::error_code ec;
    std::filesystem::create_directories(kDataDir, ec);  // no-op if it already exists

    // Reopen-per-call keeps this simple and crash-safe (no long-lived handle to
    // leak or corrupt); fine at process-creation rates.
    std::ofstream file(kEventsFile, std::ios::app | std::ios::binary);
    if (!file) {
        return;  // best-effort: never crash the sensor over a logging failure
    }
    file << json_line << '\n';

agent/transport/event_sink.cpp

The console tails that file by byte offset into SQLite, then runs every event through every rule with a shared EQL engine. A rule whose query throws is logged and skipped instead of stopping the pass.

function matchEvent(evt) {
  const alerts = [];
  for (const rule of RULES) {
    let hit;
    try {
      hit = EQL.matches(rule.query, evt);
    } catch (err) {
      console.error(`[detection] rule '${rule.name}' query error:`, err.message);
      continue;
    }
    if (hit) {
      alerts.push({ severity: rule.severity, mitreId: rule.mitreId, ruleName: rule.name, title: rule.title });
    }
  }
  return alerts;
}
