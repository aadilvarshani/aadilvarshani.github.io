ReaperWatch

A Windows EDR, built from scratch, one real mechanism at a time: a C++ agent that watches process creation as Windows reports it through ETW, and a console that turns that telemetry into alerts.

ETW PEB CNG Authenticode JSONL EQL ETW PEB CNG

2026

Why build one when EDRs already exist

I wanted the mechanical answer to a question detection engineering usually leaves as a black box: how does an EDR find out a process exists, with enough detail to judge it, as close to the moment it happens as Windows allows? Not the detection logic, the layer underneath it. ReaperWatch is me building that layer myself, in the open, including the parts that didn't work the first time.

NT Kernel Logger

Windows' own process trace session. ReaperWatch doesn't poll for processes: the kernel reports every creation through ETW as it happens.

1ETW consumer

The agent starts the NT Kernel Logger in real-time mode with the process flag set, so every process creation on the machine arrives as an event while it happens, not from a poll.

std::vector<BYTE> buffer(size, 0);

2Process monitor

Each event gets its command line from the PEB, SHA256 and MD5, the Authenticode signer, user context and two levels of lineage. A parent is only recorded if it provably started before the child, so a recycled PID never gets blamed for something it didn't launch.

// PID-reuse guard: a real parent must be no younger than its child. If the
    // PID was recycled, the process now holding it started later -> reject it.
    const auto child_time = get_process_creation_time(pid);
    const auto parent_time = get_process_creation_time(parent_pid);
    if (!child_time.has_value() || !parent_time.has_value()) {
        return;  // can't verify -> don't record an unverified parent
    }
    if (*parent_time > *child_time) {
        return;  // parent started after the child: PID reused, impostor
    }

3Event sink

Events are appended to a local JSON Lines file, whether or not anything is reading it. Writes are serialised in case ETW calls back from more than one thread, and a failed write never takes the sensor down.

void append_event_line(const std::string& json_line) {
    std::lock_guard<std::mutex> lock(g_mutex);

    std::error_code ec;
    std::filesystem::create_directories(kDataDir, ec);  // no-op if it already exists

    // Reopen-per-call keeps this simple and crash-safe (no long-lived handle to
    // leak or corrupt); fine at process-creation rates.
    std::ofstream file(kEventsFile, std::ios::app | std::ios::binary);
    if (!file) {
        return;  // best-effort: never crash the sensor over a logging failure
    }
    file << json_line << '\n';

4HTTP sender, optional

If a config file sits next to the agent, each event is also POSTed to a console over WinHTTP, authenticated with a per-console key. No config file means fully local: no network calls at all.

5events.jsonl

One JSON line per process event, always the same shape: process, parent, grandparent, user, host and flags. A missing value is written as null rather than dropped, so every event has every key.

6Ingestor

The console tails the file by byte offset into SQLite. A half-written last line is left for the next pass, and a malformed line is consumed and skipped so it can't block everything behind it.

7SQLite

Node's built-in node:sqlite, so there's no native dependency to compile. It stores the full enriched event plus a raw_json column for drill-down.

8EQL engine

Every event runs through every rule. One event can raise several alerts, and a rule whose query throws is logged and skipped instead of stopping the pass.

function matchEvent(evt) {
  const alerts = [];
  for (const rule of RULES) {
    let hit;
    try {
      hit = EQL.matches(rule.query, evt);
    } catch (err) {
      console.error(`[detection] rule '${rule.name}' query error:`, err.message);
      continue;
    }
    if (hit) {
      alerts.push({
        ts: evt.timestamp,
        severity: rule.severity,
        mitreId: rule.mitreId,
        mitreName: techniqueName(rule.mitreId),
        ruleName: rule.name,
        title: rule.title,
        detail: (evt.process?.cmdline || evt.process?.path || '').slice(0, 200),
      });
    }
  }
